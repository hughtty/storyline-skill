# storyline-director

为教育项目提供剧情故事创作的主调度技能，负责管理项目生命周期、协调子技能完成剧情素材产出。

## 核心定位

- **核心场景**：直播课教学（老师通过 PPT 教学，剧情穿插在课件中）
- **输出形态**：结构化剧情素材包（分镜脚本 + 教学节点 + 角色素材）
- **叙事结构**：三幕式（开场动画 → 中间教学节点 → 结尾动画）

## 工作流程

```
Step 1: 项目初始化
  ├── 新项目：创建目录结构、初始化角色库、世界观
  └── 延续项目：加载已有项目、确认沿用/新增角色

Step 2: 需求采集
  ├── 学科、年级/认知水平
  ├── 核心知识点（Skill 可自动搜索理解）
  ├── 课时类型：主线 / 支线 / 跨课时（第 N 部分）
  └── 出场角色选择（沿用 or 新增）

Step 3: 故事梗概生成 → 等待用户确认 ✓
  └── 调用 story-outline 子技能

Step 4: 教学节点设计 → 等待用户确认 ✓
  └── 调用 teaching-nodes 子技能

Step 5: 结尾衔接确认
  ├── 是否单元最后一课？
  ├── 如否，收集下一课知识点
  └── 确认下集预告设计

Step 6: 脚本撰写 → 等待用户 review
  └── 调用 script-writer 子技能
  └── 输出完整素材包

Step 7: 交付
  └── 输出项目文件结构概览
  └── 询问是否需要调整
```

## 确认机制

每个确认节点必须**明确获得用户通过后才进入下一步**，不可自动推进：

| 阶段 | 确认内容 | 输出文件 |
|------|----------|----------|
| 梗概 | 故事方向、角色任务、钩子设计 | story_outline.md |
| 节点 | 教学进度拆分、节点分布 | teaching_nodes.md |
| 衔接 | 是否单元结束、下集预告方向 | （对话确认） |
| 分镜 | 分镜脚本、对白内容 | *_storyboard.md |

## 钩子设计原则

- **开场**：抛出与知识点相关的角色困境（悬念钩子）
- **中间**：每完成一个知识点练习，剧情推进一小步（逐步回收钩子）
- **结尾**：解决开场困境，视情况抛出下集预告（新悬念钩子）

## 知识管理能力

storyline-director 内置数据管理和检索能力，确保项目规模增长时数据不混乱：

### 自动索引维护
每完成一个课时创作，自动更新：
- `index.json` — 项目级索引（课时列表、角色列表、知识点映射）
- `character_graph.json` — 角色出场记录、关系演变
- `episode_graph.json` — 课时关联、钩子追踪
- `knowledge_map.json` — 知识点与课时的映射

### 智能检索（RAG）
支持自然语言查询，快速定位项目中的任何信息：

| 查询类型 | 示例 | 检索范围 |
|----------|------|----------|
| 角色检索 | "找一个勇敢的角色" | character_graph + 角色档案 |
| 剧情检索 | "找有分数知识点的课时" | knowledge_map + 故事梗概 |
| 对白检索 | "小智说过'让我来'吗？" | 节点对白 |
| 跨课时追踪 | "ep01 的钩子在哪儿回收了？" | episode_graph |
| 世界观查询 | "魔法学院有什么场景？" | worldview |

### 一致性检查引擎
自动检测数据质量问题：
- **角色一致性**：核心性格是否被擅自修改
- **世界观一致性**：场景描述是否矛盾
- **剧情逻辑**：钩子是否有回收、抓手是否有对应节点
- **跨课时连续性**：主线剧情是否衔接

### 使用方式

用户输入项目信息（学科、知识点、年级等）后，按步骤引导完成整个流程。
