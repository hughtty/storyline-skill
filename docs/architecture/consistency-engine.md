# Storyline Skill — 一致性检查引擎

## 设计目标

确保随着项目规模增长（数十个课时、数十个角色），数据质量不下降——角色性格不崩、世界观不矛盾、剧情逻辑不自相冲突。

## 检查维度

### 维度 1：角色一致性（Character Consistency）

#### 1.1 核心性格不变性

**规则**：角色的"核心性格"字段在不同课时中不可被擅自修改。

**检查方式**：
```
对于每个角色：
  读取 master_library 中的核心性格
  遍历该角色在所有课时中的出场记录
    检查 story_outline.md 中的"性格适配说明"
    检查 node_scripts.md 中的对白是否符合性格
    如检测到巨大偏离 → 标记冲突
```

**示例冲突**：
- 小智的核心性格是"勇敢但莽撞"
- 在 ep05 的 story_outline 中，小智被描述为"冷静思考，从不冲动"
- **冲突级别**：严重（直接违背核心性格）
- **处理方式**：提醒用户，要求确认是否为角色成长弧光的一部分

#### 1.2 跨学科性格适配检查

**规则**：同一角色跨学科时，仅允许语言风格、知识领域的微调，不可改变性格本质。

**检查方式**：
```
对于每个角色：
  按学科分组其出场记录
  检查各学科的"性格适配说明"
  如检测到性格本质变化 → 标记冲突
```

**示例冲突**：
- 小智在数学课："对难题感到困惑但愿意尝试"（适配：莽撞→敢于挑战）
- 小智在英语课："害怕犯错，不敢开口"（偏离：勇敢→胆怯）
- **冲突级别**：中等（需要用户确认是否为剧情需要）

#### 1.3 角色关系一致性

**规则**：角色之间的关系演变应有合理铺垫，不可突兀变化。

**检查方式**：
```
遍历 episode_graph 中的时间线：
  检查相邻课时的角色关系描述
  如关系发生巨大变化但没有中间过渡 → 标记冲突
```

**示例冲突**：
- ep03：小智和小慧是"互相信任的搭档"
- ep04：小智和小慧"互相猜疑，分道扬镳"
- 但 ep03→ep04 之间没有冲突事件铺垫
- **冲突级别**：中等（需要补充过渡剧情）

### 维度 2：世界观一致性（Worldview Consistency）

#### 2.1 核心规则不变性

**规则**：世界观的核心规则（如"魔法能量=语言能力"）不可被推翻。

**检查方式**：
```
读取 worldview.md 中的核心规则
遍历所有 story_outline.md：
  检查是否有剧情违背核心规则
  如检测到 → 标记冲突
```

**示例冲突**：
- 核心规则："魔法能量=语言能力"
- ep07 中出现"用数学公式施展魔法"
- 如世界观未提前扩展"数学也是语言的一种" → 冲突
- **冲突级别**：严重（需要更新世界观或修改剧情）

#### 2.2 场景一致性

**规则**：同一地点在不同课时中的描述不应矛盾。

**检查方式**：
```
提取 worldview.md 中的所有地点描述
遍历所有 story_outline 和分镜脚本：
  检查地点描述是否与 worldview 一致
  检查同一地点在不同课时中的描述是否一致
```

**示例冲突**：
- worldview："魔法图书馆有 3 层楼，禁书区在地下"
- ep02："魔法图书馆有 5 层楼，禁书区在顶楼"
- **冲突级别**：严重（需要统一设定）

#### 2.3 时间线一致性

**规则**：世界观时间线中的事件顺序不应矛盾。

**检查方式**：
```
读取 worldview.md 中的时间线
遍历所有 story_outline：
  检查课时中提及的历史事件是否与时间线一致
```

### 维度 3：剧情逻辑一致性（Story Logic Consistency）

#### 3.1 钩子回收检查

**规则**：开场抛出的钩子必须在课时内有回收机制。

**检查方式**：
```
读取 story_outline.md 中的钩子设计
检查 teaching_nodes.md 中的钩子回收进度表
验证：
  - 每个开场钩子都有对应的回收节点
  - 回收进度从 0 到 100%
  - 结尾确实有回收动作
```

**示例冲突**：
- 开场钩子："三把锁需要说出规律才能打开"
- 教学节点：只设计了 2 把锁的回收
- 结尾：没有提到第三把锁
- **冲突级别**：严重（必须修复）

#### 3.2 教学抓手对应检查

**规则**：教学抓手设计表中的每个知识点都应在教学节点中有对应。

**检查方式**：
```
读取 story_outline.md 中的教学抓手设计表
检查 teaching_nodes.md 中的节点详情
验证：
  - 每个知识点至少有一个对应节点
  - 节点的"钩子回收进度"与知识点数量匹配
```

#### 3.3 对白与角色性格匹配

**规则**：角色在节点对白中的台词应符合其性格设定。

**检查方式**：
```
读取角色档案中的性格描述
读取 node_scripts.md 中的对白
使用语义匹配检查对白是否符合性格标签
```

**示例冲突**：
- 小智性格："莽撞、直接"
- 节点对白中小智说："根据我的分析，这道题有 3 种解法..."
- **冲突级别**：轻微（可能是角色成长，需确认）

### 维度 4：跨课时一致性（Cross-Episode Consistency）

#### 4.1 主线连续性

**规则**：主线课时的剧情应有合理的连续性。

**检查方式**：
```
读取 episode_graph.json 中的主线边
检查相邻主线课时的 story_outline：
  - 结尾预告与下集开头是否衔接
  - 角色状态是否一致（受伤/获得道具等）
```

#### 4.2 伏笔回收检查

**规则**：跨课时埋下的伏笔应在后续课时中回收。

**检查方式**：
```
遍历所有 story_outline：
  标记所有"伏笔"和"下集预告"
检查后续课时是否有对应回收
如未回收 → 标记为"待回收伏笔"
```

## 检查触发机制

### 自动触发

| 事件 | 触发的检查 |
|------|-----------|
| 创建新课时 | 钩子回收检查、抓手对应检查 |
| 修改角色档案 | 角色一致性检查（跨课时） |
| 修改世界观 | 世界观一致性检查（跨课时） |
| 完成脚本输出 | 对白性格匹配检查 |

### 手动触发

用户可以主动请求：
- "检查项目一致性"
- "检查角色小智的一致性"
- "检查 ep01-ep05 的连续性"

```markdown

- **角色**：小智

### 🟢 轻微冲突（可选修复）
```

## 实现方式

### 方案 A：规则引擎（基于 JSON 规则）

用结构化规则进行精确检查：
- 优点：准确、可解释、速度快
- 缺点：无法处理语义层面的冲突

### 方案 B：语义检查（基于 LLM）

用 LLM 进行语义层面的理解检查：
- 优点：能发现规则引擎漏掉的微妙冲突
- 缺点：慢、成本高、可能误判

### 方案 C：混合方案（推荐）

先用规则引擎快速过滤，再用 LLM 检查复杂冲突：
```
Step 1: 规则引擎快速扫描 → 标记明显冲突
Step 2: LLM 深度检查 → 发现语义冲突
Step 3: 合并报告 → 去重排序
```

## 与 RAG 系统的整合

一致性检查的结果可以反哺 RAG 系统：
- 冲突标记 → 检索时提醒用户注意
- 一致性历史 → 帮助检索系统理解"哪些设定是稳定的"
- 修复记录 → 避免重复检查已修复的问题
